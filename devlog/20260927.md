# Devlog #1: "Any sufficiently advanced technology is indistinguishable from magic".
This devlog contains the origin of the idea and the progress made from project start (~09/18) to 09/27. Likely to be updated with images at a later date.

## The Origin
It all started with this Instagram reel I saw about conductive thread earlier this summer. Somehow watching that connected a series of neurons that lead me to thinking about this project.

I wanted to cosplay something within the Witch Hat Atelier (WHA) universe, but I'm not into cosplaying as already existing characters. I'm more into putting myself into an established world and imagining what it would be like to be living in that world. Although, the character I relate to the most in the story is Olruggio. I just really love the idea of witches making magical objects for witch and non-witch consumers.

The magic system in WHA reminded me a lot of circuits (among other things like crochet diagrams) in how it worked mechanically. The caster draws the runes in certain proportions to each other and those runes are then encircled, with the closed circle activating the spell. To put very simply, with circuits you put all your pieces down, connect them, and once it's complete it should work. With that in mind I definitely wanted to do something with electronics in the costume.

I've been kicking this idea around in my head most of August until I finally wrote it down in a large notebook I got specifically for lightly fleshing out ideas.

An extension of this project is to actually make simulacrums of the magical objects that exist in the world in real life. Obviously there are some things that are physically impossible to achieve the full functionality of (currently, I guess), but would be sick like the [vapor bubble](https://witch-hat-atelier.fandom.com/wiki/Vapor_Bubble) or the [sylph shoes](https://witch-hat-atelier.fandom.com/wiki/Sylph_Shoes).

## The Hat

I started on the hat first since it's the easiest to approach from an electronics standpoint. I picked up an [Inland FT232 Starter Kit](https://www.microcenter.com/product/617246/inland-nano-ft232-starter-kit) from MicroCenter when I was in the Bay Area earlier this summer with intention of doing _something_ with it. And this became the something. I opened th kit, pulled out the components I needed for a proof of concept. I knew I at least wanted the following:

* Lights turn on when something in the hat "senses" that the brim is down.
* Light brightness can be controlled wirelessly. (The devlog will be covering this bit)

When I began putting those components on the breadboard included in the kit, I discovered the Nano's footprint was ~90% of the board and left no room for anything else. So I found an  electronics shop ([Vetco Electronics](https://vetco.net/)) that definitely had the breadboards I was familiar with. However, if I was going to make the drive out to the store, I was going to try to get other things that I needed. I did a little research on the transmit (tx) and receive (rx) modules that car keyfobs use for unlocking from a distance. The common modules appeared to be the RX480E and TX118SA.

Vetco did not have the RX/TX modules I was looking for so I had to order them online, but it was still worth going. It's a cool little spot that reminded me a bit of the electronics stores in Akihabara. It had that electronics smell to it, if you know what I mean.

Anyway despite not having the modules, I could still get started. Since I'm rusty with electronics, I went to the [projects page](https://wiki.keyestudio.com/055251_Nano_FT232_Starter_Kit) included in the kit's instructions to look at example code and wiring diagrams for how to connect [buttons](https://wiki.keyestudio.com/055251_Nano_FT232_Starter_Kit#Button-controlled_LED) and the [RGB LED](https://wiki.keyestudio.com/055251_Nano_FT232_Starter_Kit#RGB_LED).

From the reference material I was able to change the color of the RGB LED using two buttons. 

In the code, my implmentation was shaping up to be a function that contained case statements that registered the LED's state. Something like:

```
if(state == #){
    digitalWrite(redPin, <HIGH/LOW>);
    digitalWrite(greenPin, <HIGH/LOW>);
    digitalWrite(bluePin, <HIGH/LOW>);
}
```

But repeated 8 times and I didn't want to do that because it felt stupid. Also the Arduino IDE is not the friendliest. From the depths of my mind, the thought that I should be able to set these pins using binary numbers floated to the top. So I looked it up and that approach is valid. One of the buttons adds `0b000010` and the other button subtracts `0b000010`. The value can't go over `0b001110` or under `0b000000`. 

The next problem I ran into was including code that would only register when a button was pressed the first time and not held down. I ended up copying code from either Stack Overflow or the Arduino forums. Basically the code checks if the current button state is the same as the previous button state. If the states are different then it reads the state again and if the current reading is LOW and if the last reading was HIGH, then the addition or subtraction happens. This makes sure holding either of the the button down doesn't constant add or subtract from the LED value.

Once I got all that squared away, the circuit worked!

__[INSERT VIDEO OF WIRED CONTROL IF POSSIBLE]__

The next day the RX/TX modules arrived and getting that set up was pretty simple. I hooked up the RX480E to power and replaced the buttons with the pins D1 and D2. The buttons were moved to opposite end of the breadboard to be connected to pins D1 and D2 of the TX118SA. Turns out, pins 1 and 2 on the TX module do not correlate with pins D1 and D2 of the RX module. It's actually:

| RX480E Pin | Corresponding TX118SA Pin |
| ------ | ------ |
| D1 | 4 |
| D2 | 3 |
| D3 | 2 |
| D4 | 1 |

Shout out to [this guy](https://www.youtube.com/watch?v=2sVdTHcN2hg) that has a YouTube series specifically about these things.

So once that got fixed I got the same functionality, but wireless!
